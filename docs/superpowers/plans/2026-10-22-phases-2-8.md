# Phases 2–8 Implementation Plans

> Executed inline (native) right after Phase 1, per the 2026-10-22 "execute everything" brief.
> **Spec:** `docs/superpowers/specs/2026-10-22-platform-evolution-design.md`. Phase 1: `2026-10-22-phase-1-foundation.md`.

## Global Constraints (all phases)

- Each phase is a local branch cut from the previous phase. `integration/platform-evolution` merges them at the end. **No merge into `main` and no push.**
- No AI attribution in commits. Stage explicit paths.
- Every handler goes through `route()`. Writes call `requireActor({ write: true })`. Staff actions call `requirePermission()` and `recordAudit()` in the same transaction.
- Raw SQL compares timestamps with `(now() AT TIME ZONE 'UTC')`. Prisma stores UTC in `timestamp without time zone`, and the session zone isn't UTC on dev machines. This bit Phase 1.
- Lists are keyset-paginated (`lib/pagination.ts`): 20 by default, 50 max.
- User text is plain text (D9). Its tokens (mention, hashtag, url) come from `lib/rich-text.ts`.
- Banned authors' content and HELD/REMOVED/DELETED content are excluded in the query, not filtered afterwards. Authors still see their own HELD posts.
- Never seed activity. Seeds create structure only: communities with zero members, gear catalog entries, and feature flags.

## Review Focus (cross-phase)

1. **Vote races:** double-clicking up/down must leave `score` equal to the sum of the vote rows. Votes on one post are serialized with `SELECT … FOR UPDATE` on the post (P2 integration test).
2. **Visibility leaks:** a removed post, its comments, its media and its attached private tone must not show up through any list, search, tag, profile, bookmark or notification query (P2/P3/P4 tests per query helper).
3. **Upload abuse:** a renamed executable, a 2 GB file, a video with no video stream, and a decompression-bomb image must all be refused before processing finishes (P4 tests).
4. **Moderator overreach:** a community moderator can't act outside their community, a MODERATOR can't ban or change roles, and an ADMIN can't demote the last admin (P6 route tests).
5. **Legacy tones:** v1/v2 tones still open at `/t/[id]`, stay UNLISTED after migration, and can be published, remixed and compared (P3 integration test).

## Phase 2 — Social core (`feat/social-core`)

**Schema (migration `social`):** `Community`, `CommunityMember`, `Post` (+ `PostCategory` enum: DISCUSSION, QUESTION, PERFORMANCE, COVER, GEAR_DEMO, TONE_COMPARISON, TUTORIAL, PEDALBOARD), `PostTag`, `Comment`, `PostVote`, `CommentVote`, `Bookmark`, `Notification`, `Report`, `Appeal`, `ModerationRule`, `FeatureFlag`. Shapes as in spec §3. `Post.hotRank Float` is indexed with `id`. Indexes: `(status, hotRank, id)`, `(status, createdAt, id)`, `(communityId, status, hotRank)`, `(authorId, createdAt)`.

**Modules**
- `lib/rich-text.ts`: `tokenize(text): Token[]`, `extractTags(text): string[]` (≤ 10, `#[a-z0-9_]{2,40}`, lowercased), `extractMentions(text): string[]` (≤ 10 handles).
- `lib/ranking.ts`: `hotRank(score: number, createdAt: Date): number` = `sign·log10(max(|s|,1)) + (createdAt/1000 − 1767225600)/45000`.
- `lib/flags.ts`: `isEnabled(key: FlagKey): Promise<boolean>` with a 30 s in-process cache and defaults in code (`community.userCreation: true`, `uploads.video: true`, `signups: true`).
- `lib/automod.ts`: `screenText(text, author: {createdAt}) → { hold: boolean; reasons: string[] }` from enabled `ModerationRule`s (BLOCKED_TERM `{terms[]}`, LINK_HOLD_NEW_ACCOUNTS `{hours}`, MAX_MENTIONS `{max}`). `autoHoldThreshold` (3 distinct open reports → HELD) comes from the REPORT_HOLD rule `{reports}`.
- `lib/notify.ts`: `notify(input | input[])`. It skips self-notifications and banned recipients.
- `lib/communities.ts`: `canCreateCommunity(actor) → { ok } | { ok: false; reason }` (account ≥ 7 days old, not suspended, flag on, ≤ 2 created in the last 30 days, verified email once P8 enforcement is on). Also `isCommunityModerator(userId, communityId)` and `parseCommunityInput`.
- `lib/posts.ts`: `parsePostInput`, `POST_VIEW_SELECT`, `toPostView(row, viewer)`, `visiblePostWhere(viewerId)`, plus `createPost`, `editPost`, `deletePost`, `votePost(userId, postId, value)` (transaction with row lock that updates score, upCount, hotRank and author reputation), `bookmark`, and the `feed` queries: `forYou`, `following`, `community`, `tag`, `byAuthor`, `bookmarks`. Each returns `{ items: PostView[], nextCursor }`.
- `lib/comments.ts`: `createComment` (depth ≤ 6, notifies the post author or the parent author plus mentions), `listComments(postId, viewer)` (flat, sorted by score then age, capped at 500, and the client builds the tree), `voteComment`, `editComment`, `deleteComment` (soft: body → `[deleted]` when it has replies).
- `lib/moderation.ts`: `moderatePost/moderateComment(actor, id, action: "remove"|"restore", reason)`. Allowed for `content.moderate` or a moderator of that community. Writes audit and notifies the author with a MODERATION notification that links to an appeal.
- `lib/reports.ts`: `fileReport` (one open report per reporter/target, rate-limited, auto-hold at threshold) and `fileAppeal`.

**Routes:** `/api/communities` (GET list, POST create), `/api/communities/[slug]` (GET, PATCH), `/api/communities/[slug]/membership` (PUT/DELETE), `/api/communities/[slug]/posts`, `/api/posts` (POST), `/api/posts/[id]` (GET/PATCH/DELETE), `/api/posts/[id]/vote`, `/api/posts/[id]/bookmark`, `/api/posts/[id]/comments`, `/api/posts/[id]/moderation`, `/api/comments/[id]` (PATCH/DELETE), `/api/comments/[id]/vote`, `/api/comments/[id]/moderation`, `/api/feed`, `/api/tags/[tag]/posts`, `/api/users/[handle]/posts`, `/api/bookmarks`, `/api/notifications` (+ `/read`), `/api/reports`, `/api/appeals`.

**Seed:** `prisma/seed.ts` upserts ~16 communities (genres, instruments, gear, styles) with zero members, plus the default moderation rules and flags. Run with `npm run db:seed`.

**Tests:** unit tests for rich-text, ranking, post/community validation and `canCreateCommunity`. Integration tests for vote races, feed ordering and keyset continuity, visibility of HELD/REMOVED/banned content, comment depth, auto-hold at the report threshold, a community mod limited to their own community, and notifications. Route tests for auth and permission edges.

## Phase 3 — Tones & gear (`feat/tone-sharing`)

**Schema (migration `tones_gear`):** `Tone.visibility ToneVisibility @default(UNLISTED)`: existing rows and new saves stay link-only, which keeps the library share dialog working (D6). Owners publish explicitly. Also `Tone.remixOfId`, `saveCount`, `remixCount`, `publishedAt`, `description`, and a `searchText` generated column (P5). Plus `GearItem`, `ToneGear`, `ToneSave`.

**Modules**
- `types/rig.ts` + `lib/rig-validation.ts`: `RigSpec` (spec §3). Every field is optional. Params are clamped and numbers bounded, with ≤ 24 chain blocks and strings ≤ 120.
- `lib/tone-recipe.ts`: `StoredToneData` v3 `{ version: 3; recipe?: RecipeCore; rig?: RigSpec; origin: { kind: "analysis"; songId } | { kind: "manual" } | { kind: "remix"; toneId } }`. `recipeFromStoredTone` reads v1/v2/v3.
- `lib/tones.ts`: `toneViewSelect`, `canViewTone(tone, viewerId)` (PUBLIC/UNLISTED anyone, PRIVATE owner, banned owner hidden), `publishTone`, `saveTone`/`unsaveTone`, `remixTone(userId, toneId)` (copies data, credits `remixOfId`, notifies the source owner, bumps `remixCount`), `compareTones(a, b)` → a diff of amp knobs and chain blocks, `exportTone(tone)` → `resoniq-tone/v1` JSON, and `syncToneGear(toneId, rig)`.
- `lib/gear.ts`: catalog search (pg_trgm), `GEAR_KINDS`, and `controlsFor(kind)` (default knob sets).
- Seed: about 120 well-known real products across guitars, basses, pickups, amps, cabs, pedals, modelers and plugins, with factual brand/model names only.

**Routes:** `/api/tones` (existing) accepts `rig`, `visibility` and `description`. `/api/tones/[id]` PATCH accepts `recipe`, `rig`, `visibility` and `description`. New: `/api/tones/[id]/save`, `/api/tones/[id]/remix`, `/api/tones/[id]/export`, `/api/tones/compare?a&b`, `/api/tones/public` (discovery: new/popular, filters by instrument/genre/gear), `/api/gear` (search), `/api/gear/[slug]` (item with its public tones), and `/api/gear` POST (submit custom → PENDING).

**Tests:** v1/v2/v3 compatibility, legacy rows UNLISTED, rig validation edges, a PRIVATE tone hidden through every path, the remix credit chain, compare diffs, and an export round-trip.

## Phase 4 — Media pipeline (`feat/media-pipeline`)

**Schema (migration `media`):** `Media` (spec §3), plus `User.avatarMediaId` and `bannerMediaId`.

**Modules**
- `lib/media/sniff.ts`: `sniffMedia(bytes) → { kind, ext, mime } | null` for MP4/MOV (ftyp brands), WebM/Matroska (EBML), JPEG, PNG, WebP, GIF→refused, plus the existing MP3/WAV/FLAC.
- `lib/media/limits.ts`: `MEDIA_LIMITS` (video 500 MB / 600 s, audio 50 MB / 900 s, image 15 MB / 40 MP), `DAILY_UPLOAD_BYTES = 3 GB`, `MAX_ATTACHMENTS = 10`.
- `lib/storage.ts`: key pattern extended to `media/<userId>/<mediaId>/<name>.<ext>`. Adds `putStream` (local: a streamed write with a byte cap) and `signedUrl(key, ttl)` (Supabase), plus `stat`/range reads for local.
- `lib/media/service.ts`: `createUpload(actor, {kind, size, mime})` → Media row (UPLOADING) after the quota check. `receiveUpload(mediaId, stream)` streams to storage with a byte cap and sniffs the first 4 KB. `finalize` enqueues `media.process`. Removal enqueues `media.purge` with `runAt` +30 days.
- `worker/media.ts` (`media.process` handler): `ffprobe` JSON → validate streams and duration → `ffmpeg` transcode (H.264 High, CRF 23, max 1080p, AAC 128k, `+faststart`), poster at 10% of the duration, a 4 s muted preview loop at 480p, and audio extraction to FLAC → a `Song` (UPLOADED) linked through `Media.songId`. Images are re-encoded to WebP (max 2560 px, metadata stripped). Audio is normalized to AAC M4A plus a waveform peaks JSON. A ffmpeg timeout of 15 min and `-threads 2` keep the worker bounded.
- `GET /api/media/[id]/[variant]` with variant `playback|poster|preview|original`. Access is `canViewMedia` (READY + visible post, or owner/staff). Range support comes from `lib/http-range.ts`. Supabase → a 302 to a 5-minute signed URL. Cache: `private, max-age=300`.
- Upload API: `POST /api/media` (create), `PUT /api/media/[id]/content` (streamed body; progress via XHR), `GET /api/media/[id]` (status polling), and `DELETE`.
- CSP gains the Supabase origin for `img-src`/`media-src` when it's configured.

**Tests:** sniffing every type plus refusals, quota math, the key pattern, a streamed write over the cap that aborts and cleans up, `canViewMedia` across post states, and the `media.process` handler run on tiny fixture media generated with ffmpeg during the test (skipped when ffmpeg is missing). Includes the bad-file cases from Review Focus 3.

## Phase 5 — App experience (`feat/app-experience`)

**Design system:** evolved tokens in `globals.css` (surface ramp, copper and signal scales, line colors, a type scale with display sizes to 9rem, spacing, radii, motion durations), documented in `docs/design-system.md`.

**Icons:** `components/icons/` holds about 40 custom glyphs (24 grid, 1.75 stroke): guitar, bass, amp head, combo, cab, pedal, multi-fx, modeler, plugin, pickup, tuning fork, signal chain, knob, fader, waveform, spectrum, analyze, tone preset, remix, compare, community, feed, explore, search, bell, bookmark, amp-up vote, down vote, comment, share, upload, video, image, audio, settings, shield, flag, user, users, gear catalog.

**Shell:** `app/(app)/layout.tsx` with a desktop sidebar (≥ 1024), a tablet icon rail (768–1023) and a mobile bottom tab bar plus a top bar (< 768). The existing `/library`, `/analyze` and `/t/[id]` move into the group with unchanged URLs.

**Surfaces:** `/feed`, `/explore`, `/search`, `/c`, `/c/[slug]`, `/c/new`, `/u/[handle]` (+ followers/following), `/p/[id]`, `/new` (composer), `/tones`, `/t/[id]` (rig inspector, inferred vs declared, save/remix/compare/export/publish), `/compare`, `/gear`, `/gear/[slug]`, `/tag/[tag]`, `/notifications`, `/bookmarks`, `/settings` (profile, account, privacy, danger zone), `/copyright`, `/appeals`. Analyze → "Save & publish" flows into the composer with the tone attached.

**Search (migration `search`):** generated `tsvector` columns plus GIN on Post, Tone and Community. `pg_trgm` on `User.handle`/`name` and `GearItem`. `lib/search.ts` exposes `search(q, type, cursor)`.

**Tests:** unit tests for the client helpers (comment tree building, upload progress reducer, rich-text rendering escapes) and search integration tests. Accessibility: each page has landmarks, labelled icon buttons, and focus management in dialogs.

## Phase 6 — Admin console (`feat/admin-console`)

`app/admin/layout.tsx` (it calls `requirePermission` for any staff permission, otherwise 404) with its own sidebar and icons. Pages: overview (KPIs plus 30-day SVG charts from SQL `date_trunc` aggregates), users (search, detail, suspend/ban/unban, role change gated by `users.roles`, last-admin guard), content (posts/comments with status filters, remove/restore), media (failed/processing/removed, re-run), reports queue (grouped by target, action or dismiss), appeals (uphold/reverse → restore content or lift suspension), rules (moderation rules CRUD), communities (archive, appoint moderators, edit), curation (FeaturedSlot CRUD per placement), gear (approve/reject pending, edit), tones (unpublish), announcements (CRUD, shown as a banner in the app shell and as notifications), flags (toggle), system (job counts by status/type, failed jobs with retry, DB and engine health, storage driver), audit (filterable log).

API under `/api/admin/*`. Every handler uses `requirePermission(<perm>)` and a transactional `recordAudit`. Tests: one route test per admin mutation (permission denied, audit written) and the overreach cases from Review Focus 4.

## Phase 7 — Landing & brand (`feat/landing-evolution`)

- Brand: four logo directions as optimized SVG in `public/brand/explorations/` (A "Signal Q": an oscilloscope trace closing a Q; B "Pickup Grid": six pole pieces forming an R; C "Knob Mark": a numbered rotary at 7; D "Wordmark Monoline": a custom-drawn RESONIQ with a waveform crossbar). One is selected, then finalized as wordmark, symbol, app icon (512/192/180), favicon SVG and ICO, and light/dark lockups. `docs/brand.md` covers the rationale and usage rules.
- Illustrations: detailed SVG guitar (offset body), bass (P/J), amp head faceplate, 2×12 cab, and pedal close-ups as React components with layered gradients.
- Social templates: SVG/HTML templates in `public/brand/social/` (tone card 1080², story 1080×1920, OG image 1200×630) plus a dynamic OG route for tones and posts (`next/og`).
- Landing sections: an oversized hero (editorial type, a layered CSS-3D pedalboard plus a live analyzer composition), a "the ecosystem" bento (feed, community, tone, gear, video) using real components with live data or explicit "Example" labels, a how-it-works pipeline, a tone-inspector interactive demo (real Knob/Pedalboard components), gear close-ups, community directory (live), trending tones and posts (live, hidden when empty), a dense footer.
- No invented counts. Live sections render only real rows.

## Phase 8 — Hardening (`chore/platform-hardening`)

- Email verification and password reset: `VerificationToken` (existing model) for both, `lib/mailer.ts` (SMTP via `RESONIQ_SMTP_URL`, or a console transport in dev that logs the link), and routes `/api/auth/verify` and `/api/auth/reset` (+ request). Tokens are hashed, single-use, expire after 24 h / 1 h, and requests are rate-limited. `REQUIRE_EMAIL_VERIFICATION` gates posting and community creation.
- Smoke test extended: register → verify (dev link) → profile → follow → post → vote → comment → report.
- Query review: EXPLAIN on feed/search with seeded volume, and missing indexes added.
- Caching: landing and explore aggregates via `unstable_cache` (60 s) with tag revalidation on curation changes.
- Docs: README (services, env, seed, admin bootstrap, worker, ffmpeg), SECURITY (new controls and gaps), ROADMAP, `.env.example`, `docs/deploy.md` (hosting requirements and credentials).
- Final: integration branch, all checks, report.
